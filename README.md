# poh-sprint-report

PDF-отчёт команды по спринту для техлида и PO: две книжные страницы A4 на команду, каждое утро.
Сам ходит в Jira (только чтение), ни от чего больше не зависит: Python 3.10+ без сторонних пакетов и headless Chrome для печати.

```bash
python3 -m sprint_report demo                 # отчёт на вымышленной команде — посмотреть без Jira
python3 -m sprint_report run -c config.json   # сбор из Jira → PDF в state_dir/<день>/
```

## Что в отчёте

**Страница 1 — что делать сегодня.**

| Блок | Вопрос | Как считается |
|---|---|---|
| Прогноз спринта | Какую долю объёма закроем к концу? | (объём − остаток к концу при текущем темпе) / объём. Темп — закрыто за рабочий день с начала спринта. ▲▼ — к прогнозу вчера |
| Закрываем в день | Ускоряемся или нет? | Закрытые задачи по дням спринта; число — среднее за 5 рабочих дней, ▲▼ — к предыдущим 5. Красный пунктир — сколько нужно закрывать в день, чтобы успеть |
| В работе одновременно | Не распыляемся? | Задачи в работе, ревью, отладке и блоке на конец каждого дня. Пунктир — ориентир 1,5 задачи на человека |
| Где ждут дольше | Куда ставить людей? | Средние дни без смены статуса по этапам: блок, работа, ревью, отладка; худший — красным |
| Успеем к …? | Хватит ли темпа? | Сгорание: факт, идеал, пунктир прогноза и разрыв к концу спринта |
| Решения на сегодня | Что делает техлид | Снять блоки · Провести ревью и отладку · Разморозить застой (> 3 раб. дн. без смены статуса) · Не успеваем — оповестить PO (не начатые, крупные первыми, на величину разрыва) · Оценить и декомпозировать (без оценки и ≥ 8 SP). Номера задач — ссылки в Jira |
| Сроки и обещания | Что обещали и не сорвём ли | Эпики с целевой датой и обещания из `promises_file`: исполнитель, статус, отклонение от срока в днях |
| Эпики в спринте | Двигаются ли эпики | % готовности, полоса: готово / закрыто за 2 недели / в работе / в блоке; квадраты — истории этого спринта |

**Страница 2 — доска.** Команда (кольца статусов задач по людям), «Стоит дольше всего» (блок и застой на одной шкале дней), Kanban: в блоке, в работе, ревью, отладка, готово за день.

## Из снимка PO-Sprint-observe — вкладка «Блокаторы»

```bash
python3 -m sprint_report observe --data <observe>/workspace/reports/sprint-report.data.json --team live > live.html
```

Тот же отчёт, но из снимка виджета PO-Sprint-observe (runner `actual-sprint`), без Jira и Chrome: HTML для экрана —
листы A4 по центру, высота по содержимому, без скриптов — масштаб по ширине задаёт оболочка (печать прежняя). Так дейлик стоит вкладкой «Блокаторы»
в отчётах `/sprints/` рядом со «Спринтом» и «Бизнесом» и обновляется вместе с ними по «Актуализировать».
Упрощения: в снимке нет SP — сгорание числом задач; подзадачи не берутся (`sprint_report/observe.py`).

## Подключение к Jira

1. Скопируйте `config.example.json` в `config.json` и заполните `jira.url` и команды: `slug`, `name`, `board` — номер доски.
2. Токен — в переменной окружения (`jira.token_env`, по умолчанию `JIRA_TOKEN`) или в файле `jira.token_file`
   (одна строка с токеном или строки `KEY=VALUE`). Jira Server/DC — Personal Access Token (Bearer);
   Jira Cloud — API-токен и почта в `jira.user` / `jira.user_env` (Basic).
3. Корпоративный CA — путь к бандлу в `jira.ca_bundle`. Проверка сертификата не отключается.
4. Колонки статусов определяются по категории Jira и имени статуса (блок, ревью, тест). Если у команды
   статус значит другое — `status_buckets`: `{"Ожидает релиза": "review"}`. Колонки: `open`, `progress`, `review`,
   `testing`, `blocked`, `done`.
5. Поля Story Points, «Ссылка на эпик» и целевая дата эпика находятся по имени (`auto`); можно задать id: `customfield_10101`.
   Нет поля оценки или `"unit": "issues"` — сгорание считается числом задач.

Проверка без сети: `collect --record DIR` сохраняет ответы Jira (без токена), `collect --replay DIR` работает из них.

## Обещания

`promises_file` — JSON по командам: `{"alpha": [{"id": "P-1", "who": "Громов Кирилл", "what": "…", "due": "2026-10-20", "done": false}]}`.
Обещание попадает в отчёт команды, если фамилия из `who` есть среди исполнителей её задач.

## Расписание и отправка

`run --send` отправляет подпись по командам (блоки по давности D10+/D5+/D3+, переходы за сутки и за 2–3 сутки) и PDF
в комнату Matrix из раздела `deliver.matrix`. Токен — уже выданный access token бота: новой авторизации нет,
чтобы не выбить сессию работающего бота. Без `deliver` отчёт остаётся файлами.

systemd: `deploy/sprint-report.service` и `.timer` (будни 08:40 МСК) → `~/.config/systemd/user/`,
секреты — в `~/.config/sprint-report/secrets.env` (права 600), затем `systemctl --user enable --now sprint-report.timer`.

## Снимок

`collect` пишет на каждую команду `state_dir/<день>/snapshots/<slug>.json` — из него отчёт считается без сети.

```
schema, team{slug,name}, jira, board, collectedAt, unit ("SP" | "задач"), statusBuckets{статус: колонка},
sprint{id,name,start,end},
issues[{key,title,type,subtask,status,bucket,assignee,sp,epic,created,entered,left,
        history[{at,from,to,by}], comments[{at,by,body}]}],
epics[{key,title,due,children[{key,status,category,bucket,assignee,created,doneAt,inSprint}]}]
```

## Как считается и где упрощено

- Дни «без движения» и в блоке — рабочие, от последней смены статуса до 10:30 дня отчёта.
- Сгорание: объём — задачи (без подзадач), вошедшие в спринт к концу дня и не вышедшие; закрыто — вошедшие в «готово»
  к концу дня, переоткрытие сбрасывает. Оценка — текущая: переоценка задачи посреди спринта не видна как изменение объёма.
- Задачи, убранные из спринта, Jira в списке спринта не отдаёт — их нет и в сгорании.
- Прогноз линейный: темп с начала спринта.

## Разработка

```bash
python3 -m unittest discover -s tests -v
python3 -m sprint_report demo --day 2026-10-15 --html-only
```

Код: `jira.py` (клиент только на чтение) → `collect.py` (снимок) → `metrics.py` (цифры) → `render.py` (HTML) → `pdf.py` (Chrome) → `deliver.py`.
